# Historical casebook: inspected source-linked failure and success examples

**Source class:** linked GitHub issue or PR description, plus project agent/audit/evidence documents inspected in the 2026-10-31/11-01 snapshot. This is a curated *deeper selection* after a full PR metadata enumeration; it is not a complete manual diff/review/Actions audit. Each outcome is scoped to the cited artifact/date. Check current live source before reusing the claim.

| ID | Project and primary evidence | Observed pattern | Countermeasure / decision test |
|---|---|---|---|
| CH-01 | [Chunks issue #568](https://github.com/gamesbyian/Chunks/issues/568), [PR #864](https://github.com/gamesbyian/Chunks/pull/864) | A universal non-clobber premise treated ordinary user-selected torrent payload reuse as impermissible, prompting a long bespoke JNI writer research stack. #568 closed as **superseded**, not retrospectively passed. | Separate authorized regular payloads from app-private records and unrelated files; consult libtorrent behavior and user intent before new backend. Retain symlink, escape and non-regular-file protections. |
| CH-02 | [Chunks #809](https://github.com/gamesbyian/Chunks/issues/809) | Unlike CH-01, real ZIP/library publication could touch a substituted target or truncate an unexpectedly reused SAF URI. Unsafe shipping executors were refused. | Capability-local stop and actual provider-specific Create New/Keep Both, reviewed Replace and independent readback before restoring action. |
| CH-03 | [Chunks #865](https://github.com/gamesbyian/Chunks/issues/865), [PR #889](https://github.com/gamesbyian/Chunks/pull/889) | Repeated resume writes generated permanent files. PR description reports a real JNI lifecycle accumulating 36 events / 421,407 bytes over three cycles; SQLite changes aimed for bounded retention. | Prefer standard transactions with durable migration/retirement authority, real restart/Remove/re-add, data preservation and independent storage review. Host measured growth does not establish physical power-loss durability. |
| CH-04 | [Chunks #810](https://github.com/gamesbyian/Chunks/issues/810) | HTTP auth transmitted literal account, while profile/privacy keys trimmed it; async completion could consult mutable username. | Freeze actual authenticated identity at start; use exact account scope for privacy unlock and saved environments. |
| CH-05 | [Chunks PR #891](https://github.com/gamesbyian/Chunks/pull/891), [PR #898](https://github.com/gamesbyian/Chunks/pull/898) | First fixed a false-green read-only **test**, but shipping Android Connect still treated public version/inventory RPC as proof of supplied credentials. #898 connected the same challenged-auth gate to the production path. | Verify the supplied credentials were challenged in real transport; tests alone do not repair caller. Treat public anonymous reads distinctly. |
| CH-06 | [Chunks PR #892](https://github.com/gamesbyian/Chunks/pull/892), [PR #906](https://github.com/gamesbyian/Chunks/pull/906) | Oversize inventory pages and stopped Add outside rTorrent main view challenged completeness and exact-hash reconciliation. | Test per-hash, across all relevant views and page boundaries; don't assume a collection view or RPC ACK proves full inventory. |
| CH-07 | [Chunks engineering protocol](https://github.com/gamesbyian/Chunks/blob/main/docs/ENGINEERING-DELIVERY-PROTOCOL.md), [PR #869](https://github.com/gamesbyian/Chunks/pull/869) | Harness SIGPIPE, emulator boot and a callback-count assertion confused failure triage despite durable outcome. | Separate harness/runtime vs real product assertion, assert persisted result and rerun exact head, retaining red receipts. |
| GL-01 | [Glimpse #72](https://github.com/gamesbyian/Glimpse/issues/72), [PR #149](https://github.com/gamesbyian/Glimpse/pull/149) | CI APK signer fingerprints differed between main builds. #149 verified populated in-place upgrade under a temporary *shared per-run* test key, not permanent owner signer. | Reject uninstall-as-workaround; require persistent signing, signer fingerprint, adb install -r, preserved Room rows and SHA photo bytes before owner distribution. |
| GL-02 | [Glimpse PR #141](https://github.com/gamesbyian/Glimpse/pull/141), [issue #143](https://github.com/gamesbyian/Glimpse/issues/143) | A precheck + renameTo was replacement-prone. JVM-valid hardlink publication failed on API34 Android. CREATE_NEW made exclusive reservation possible but allowed crash-time partial visibility. | Test actual Android semantics; preserve conflicting originals, stage/force/verify bytes, track durable provenance and non-destructive interrupted recovery. |
| GL-03 | [Glimpse audit #120](https://github.com/gamesbyian/Glimpse/issues/120), [PR #118](https://github.com/gamesbyian/Glimpse/pull/118) | A bounded 12k-row SQL window helped but did not prove full Home/Reel composition or physical scrolling performance. | Differentiate DB query complexity from Compose/Bitmap/host performance; profile actual scroll/recomposition before claiming optimization. |
| GL-04 | [Glimpse PR #142](https://github.com/gamesbyian/Glimpse/pull/142), [PR #135](https://github.com/gamesbyian/Glimpse/pull/135) | Actual AppWidgetHost and picker integration, plus observed UI feedback obscured by anchored reel, required integrated/emulator and screenshot acceptance. | Verify real Android host/window and inspect rendered artifact; green unit models and pretty structural SVG are different evidence tiers. |
| GL-05 | [Glimpse PR #166](https://github.com/gamesbyian/Glimpse/pull/166), [PR #168](https://github.com/gamesbyian/Glimpse/pull/168) | A negated phrase containing an issue-closing GitHub keyword auto-closed unfinished #143 on merge. | Write “Issue #143 remains open” without an auto-closing verb adjacent to #143 and inspect P0 issue state after merging partial work. |
| EX-01 | [Expository #222](https://github.com/gamesbyian/Expository/issues/222) | API35 DocumentsUI PickActivity appeared in logcat but UiAutomator could not locate its window; failure happened before transfer, while prior E2 had passed. | Diagnose system-window/root visibility first; never substitute pre-granted URI or infer a file-transfer regression without entering operation. |
| EX-02 | [Expository PR #292](https://github.com/gamesbyian/Expository/pull/292), [release ledger](https://github.com/gamesbyian/Expository/blob/main/docs/android-transfer/RELEASE-READINESS.md) | Multiple failed attempts stopped before the second picker; later accepted actual two-authority provider fixture and independently read back 137,119 bytes, nested folder and empty folder. | Real OS grants + actual copied data prove E2; synthetic fixtures have deliberately limited E4 scope. |
| EX-03 | [Expository #324](https://github.com/gamesbyian/Expository/issues/324), [PR #374](https://github.com/gamesbyian/Expository/pull/374) | Single and Dual could own divergent approval state. First merged frozen Copy authority witness did **not** claim complete dispatcher or operation execution. | Incremental shared immutable source/destination scope, maintain existing stronger route checks, then migrate and verify additional callers. |
| EX-04 | [Expository #325](https://github.com/gamesbyian/Expository/issues/325), [PR #375](https://github.com/gamesbyian/Expository/pull/375) | An opaque journal lacked enough protected operator recovery context. A fresh read-only picker/inspection added bounded review without silently reconciling/replaying. | Keep encrypted manual hints separate from no-secret core journal, reauthorize and independently observe before any new action; UNCERTAIN stays sticky. |
| EX-05 | [Expository #366](https://github.com/gamesbyian/Expository/issues/366), [PR #367](https://github.com/gamesbyian/Expository/pull/367) | Workflow-level path filters could suppress native CI on rename-out before a runtime selector saw old filenames; change lists can truncate. | Cheap always-dispatched selection + old/new paths, count integrity, unknown-impact fail-closed and stable required checks. |

**What this casebook does not prove:** exhaustive review of each artifact's full diff/threads/CI, permanent owner signing, physical-device acceptance, live protected-host mutations or complete outstanding release criteria. Historic acceptance is never automatically current acceptance.
